## 3. Репозиторий `deadlock-cb`: что внутри

**Назначение.** Независимая платформа для косметики Deadlock: каталог, история цен, коллекции, вход через Steam, маркетплейс в sandbox-режиме, админ-панель на 19 разделов.

**Стек.** Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 3, Prisma 6 + PostgreSQL 16, Redis (ioredis, опционально), zod, pino, framer-motion, Vitest, Playwright, Docker Compose.

**Объём.** 263 файла, 6 миграций Prisma, около 50 моделей, 7 unit- и 6 integration-наборов тестов, 6 e2e-сценариев Playwright. Документация в `docs/` (архитектура, безопасность, деплой, дизайн-система, итоговый отчёт).

**Гигиена секретов.** `.env` и `.env.*` исключены из Git, есть `.env.example`; в нём заполнены только несекретные значения по умолчанию. Секреты читаются только из `process.env` через zod-схему (`src/lib/env.ts`). Логгер маскирует поля `password`, `secret`, `token`, `authorization`, `cookie`.

**Готовность к запуску.** По README и `docs/FINAL_REPORT.md` проект проходит 58 unit-, 57 integration- и 33 e2e-теста. Сам я тесты в этой сессии не запускал: установка зависимостей стороннего репозитория была заблокирована политикой песочницы. Поэтому цифры выше взяты из документации, а не проверены мной. Для нашей задачи это не критично, потому что код переносится выборочно и будет покрыт собственными тестами.

## 5. Что не переиспользуем

Платежи (ЮKassa, CloudPayments, sandbox), маркетплейс и заказы, Steam OpenID, каталог предметов и цены, коллекции, рассылки по email, лидерборд, рефералы, промо. Redis в MVP не нужен: один пользователь, одна машина.

## 6. Найденные ошибки и незавершённые функции

В контексте WHYTHEWEAKEST OS: всё, что требует спецификация, ещё не начато. Telegram-бота, AI-слоя, транскрибации, извлечения ссылок, редактора публикаций, календаря и аналитики канала нет нигде.

По `deadlock-cb` замечания, важные при переносе кода:

1. Очередь задач завязана на PostgreSQL (`FOR UPDATE SKIP LOCKED` в сыром SQL). На SQLite этот запрос не работает, нужна своя реализация захвата задачи.
2. `once-store` без Redis хранит ключи в памяти процесса и теряет их при перезапуске. Для дедупликации Telegram-обновлений нужна уникальная запись в БД, а не память.
3. `captureError` только пишет в лог, Sentry не подключён (так и задокументировано).
4. Скрипты бэкапа на bash; основная ОС разработки владельца Windows 11, нужен PowerShell-вариант или запуск в Docker/WSL.

## 7. Риски и ограничения, которые видны уже сейчас

1. **Telegram Bot API не отдаёт просмотры постов канала.** Реакции на посты бот получает только как агрегированные счётчики, если он администратор канала. Просмотры и пересылки потребуют ручного импорта или отдельного MTProto-клиента от аккаунта владельца (вопрос к владельцу).
2. **У Telegram нет ключа идемпотентности для отправки.** Если запрос на публикацию оборвался по таймауту, неизвестно, вышел ли пост. Система должна в этом случае останавливаться и спрашивать владельца, а не повторять отправку.
3. **Лимит загрузки файлов ботом 20 МБ** (`getFile` облачного Bot API). Длинные видео бот скачать не сможет; нужно хранить ссылку на сообщение и предупреждать.
4. **Claude не транскрибирует аудио.** Для голосовых нужен отдельный сервис (облачный Whisper-класса или локальная модель).
5. **Доступ к Dashboard с iPhone.** Если система работает на домашнем Windows-ПК, нужен защищённый туннель (например, Tailscale) или VPS. Это решение владельца.
